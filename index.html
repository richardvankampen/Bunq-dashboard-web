Herstel hier de verbinding met Bunq en Vaultwarden zonder opnieuw te deployen. Nieuwe versies installeren en de service herstarten doe je op de NAS in de terminal; de knoppen onder Terminal tonen de commando's.

Welk probleem heb je?

Klik op je situatie voor de stappen. Begin bij twijfel met Status controleren: de status geeft ook een advies.

Het dashboard toont geen Bunq-gegevens of meldt "Incorrect API key or IP address"
  1. Klik op Status controleren. Staat API-status op Niet geïnitialiseerd, lees dan Laatste Bunq-fout en Advies.
  2. Noemt de fout het IP-adres of de API key: klik op Egress-IP controleren om te zien met welk publiek IP het dashboard Bunq benadert.
  3. Voer Volledig onderhoud uitvoeren uit met Whitelist-IP (egress) automatisch bepalen aan. Dat zet dit IP op de Bunq-whitelist en bouwt de verbinding opnieuw op.
  4. Werkt het daarna nog niet: gebruik Bunq-whitelist via terminal; dat script herstart ook de service.
Je publieke IP-adres is veranderd (nieuwe provider, router of VPN)
  1. Bunq accepteert de API key alleen vanaf IP-adressen op de whitelist. Na een IP-wissel faalt de verbinding tot het nieuwe IP erop staat.
  2. Voer Volledig onderhoud uitvoeren uit met Whitelist-IP (egress) automatisch bepalen aan.
  3. Staat het oude IP er nog en gebruik je het niet meer, zet dan Zet andere ACTIVE whitelist IPs op INACTIVE aan, of gebruik Bunq API-whitelist-IP instellen (vraagt per stap om bevestiging).
Je hebt een nieuwe Bunq API key gemaakt
  1. Zet de nieuwe key in het Vaultwarden-item (of, zonder Vaultwarden, in het Docker secret bunq_api_key).
  2. Voer de commando's van Nieuwe API key via terminal uit. Het script haalt de nieuwe key op, zet het IP op de whitelist en herstart de service, zodat alle processen van het dashboard de nieuwe key gebruiken.
  3. Geen toegang tot de terminal? Gebruik Volledig onderhoud uitvoeren met API key vernieuwen aan. Dat vernieuwt de key alleen in het proces dat het verzoek afhandelt; herstart de service later alsnog.
Vaultwarden geeft een fout (token mislukt, item niet gevonden)
  1. Klik op Status controleren en kijk naar de Vault-regels.
  2. Vault-token: Mislukt: de client_id/client_secret-secrets kloppen niet of Vaultwarden is niet bereikbaar via HTTPS.
  3. Vault-item: Niet gevonden: de naam in VAULTWARDEN_ITEM_NAME (.env) moet precies gelijk zijn aan de naam van het item (hoofdlettergevoelig).
  4. Na het aanpassen van .env of secrets is een volledige deploy nodig: zie Nieuwe versie installeren (de regel met install_or_update_synology.sh). Bekijk de details in de logs.
Transacties ontbreken, zijn gewijzigd of in Bunq verwijderd
  1. Nieuwe transacties komen binnen bij het vernieuwen; wacht een minuut en klik op Vernieuwen.
  2. Klopt het daarna nog niet, voer dan Controle met Bunq uitvoeren uit. Dat haalt alle transacties opnieuw op en werkt de opslag bij (toevoegen, bijwerken, verwijderde verbergen). Dit gebeurt ook elke maand automatisch.
  3. Het resultaat zie je daarna bij Laatste controle met Bunq in de status.
Cijfers lijken verouderd of kloppen niet na een storing
  1. Klik op Vernieuwen in de header.
  2. Helpt dat niet, voer dan Volledig onderhoud uitvoeren uit met Runtimecache wissen aan: dat gooit tijdelijk bewaarde antwoorden en wisselkoersen weg.
  3. Ontbreken er transacties, zie dan de situatie hierboven.
Er is een nieuwe versie van het dashboard
  1. Code-updates installeer je op de NAS, niet vanuit het dashboard.
  2. Alleen code gewijzigd: gebruik de snelle redeploy. Heb je .env, docker-compose.yml, secrets of het netwerk aangepast: gebruik de volledige install/update.
  3. Herlaad daarna de pagina geforceerd (Ctrl+F5 / Cmd+Shift+R).
Het dashboard is traag, hangt of herstart steeds
  1. Bekijk de logs op fouten (Vaultwarden, API key, whitelist).
  2. Herstart de service met Herstarten en controleren: het script wacht tot de start gelukt is en meldt wat er misgaat.
  3. Zie ook TROUBLESHOOTING (secties 1 en 5).
Wat doet elke knop?
  • Status controleren (alleen lezen): toont de toestand van de Bunq-verbinding, Vaultwarden, de transactieopslag en de laatste controle met Bunq, met een advies.
  • Egress-IP controleren (alleen lezen): toont het publieke IP waarmee het dashboard Bunq benadert. Dit IP moet op de Bunq-whitelist staan.
  • Bunq API-whitelist-IP instellen (wijzigt de whitelist bij Bunq): zet één IP op de whitelist in 2 stappen, elk met bevestiging: eerst het IP toevoegen of activeren, daarna desgewenst de andere IP's deactiveren. Gebruikt het IP-veld; leeg = het huidige egress-IP.
  • Alleen context opnieuw opbouwen (gevorderd): haalt de API key opnieuw op en registreert het dashboard opnieuw bij Bunq (installation + device). Wijzigt de whitelist niet en negeert de opties hieronder.
  • Volledig onderhoud uitvoeren (aanbevolen herstel): wist desgewenst de cache, bouwt de Bunq-verbinding opnieuw op en zet het IP op de whitelist, volgens de opties hieronder. Vraagt eerst om bevestiging.
  • Controle met Bunq uitvoeren: haalt alle transacties opnieuw op en werkt de opslag bij, zoals de maandelijkse controle. Loopt op de achtergrond (enkele minuten).
  • Terminal-knoppen: tonen kant-en-klare commando's met uitleg voor de NAS (installeren, herstarten, whitelist, nieuwe API key, logs).

Whitelist-opties (voor Volledig onderhoud uitvoeren en Bunq API-whitelist-IP instellen)

Aan: het dashboard gebruikt het publieke IP waarmee het nu Bunq benadert (meestal wat je wilt). Uit: vul zelf een publiek IP in, bijvoorbeeld als het dashboard via een VPN naar buiten gaat.

Aan: alleen het doel-IP blijft actief, oude IP's verliezen toegang. Laat uit als nog een ander systeem met dezelfde API key werkt.

Opties voor Volledig onderhoud uitvoeren

API key vernieuwen: haalt de key opnieuw uit Vaultwarden. Context opnieuw opbouwen: nieuwe registratie bij Bunq, lost verlopen of ongeldige sessies op. Cache wissen: gooit tijdelijk bewaarde antwoorden en wisselkoersen weg (je gegevens blijven bewaard).
